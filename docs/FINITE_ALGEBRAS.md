# Certified finite word bases and exact algebra operations

A finite word-basis certificate identifies a basis of a presented algebra and
supplies its regular generator actions. This gives exact coordinates and
products over the declared field without requiring a complete Gröbner basis.
The field can be the rationals, a checked prime field, or a rational-function
field over either; generic parameter fields are the principal research setting.

The implementation is in
[`verification/finite.py`](../src/zipper_algebra/verification/finite.py), with
shared ideal-membership proofs in
[`verification/derivations.py`](../src/zipper_algebra/verification/derivations.py).
For parameter-field verification, install the symbolic arithmetic dependency:

```sh
python -m pip install '.[symbolic]'
```

Ground-field verification needs no optional dependency. The
[parameter-field guide](PARAMETER_FIELDS.md) describes the coefficient domains
and literal presentation identities.

## Why the certificate proves a basis

Let `A = F/I`, where `F = K<g_1,...,g_m>` and `I` is generated by the ordered
input relations `r_i`. The candidate data are distinct words
`B = (b_0=1,b_1,...,b_(d-1))` and `d` by `d` matrices `M_s`, one for each
generator. Column `j` of `M_s` is the proposed coordinate vector of `g_s b_j`.
The verifier checks three assertions:

1. For every generator and every basis word, an exact cofactor derivation proves
   `g_s b_j - sum_k (M_s)_(k,j) b_k` belongs to `I`.
2. Every original relation satisfies `r_i(M_1,...,M_m) = 0` as a matrix.
3. The proposed words satisfy `b_j(M_1,...,M_m)e_0 = e_j`.

The first assertion proves spanning: the span of the images of `B` contains
`1` and is stable under left multiplication by every generator. Induction on
word length gives all of `A`.

The second assertion defines a representation of `A` on `K^d`. The third proves
independence of the named words: applying any linear relation among their
images to `e_0` gives the same linear relation among the coordinate vectors
`e_j`, so every coefficient is zero. Together these checks prove
`dim_K A = d`, and identify the supplied matrices as the left regular actions
in the certified word basis.

Both halves are required. A cyclic representation can be a proper quotient of
`A`, while spanning identities alone allow a dependent spanning family. The
matrix relation check uses every column; vanishing only on `e_0` is insufficient.
Words act in their written multiplication order, so the rightmost generator
matrix acts on a vector first.

The zero algebra has separate data: an empty word basis and a derivation of
`1 in I`. Its action matrices are all `0` by `0`. Empty matrices alone do not
supply the necessary unit-ideal proof.

## Certificate data and interchange

The public types are:

| Type | Contents |
| --- | --- |
| `GeneratorAction(field, columns)` | Immutable sparse matrix columns; each entry is `(row, FieldElement)`. |
| `DerivationTerm(coefficient, left, kind, index, right)` | A contextual multiple of an input relation or another proof node. |
| `DerivationGraph(presentation_hash, nodes, derivations)` | Exact local polynomial identities with acyclic dependencies. |
| `WordBasisCertificate(presentation_hash, basis_words, actions, proof, action_nodes, unit_node=None)` | Named basis, ordered generator actions and their ideal-membership witnesses. |

Matrix rows and columns, input relations, proof nodes and action-node references
are zero-based. Letters in word tuples are one-based generator indices; `()`
is the empty word. Actions follow the presentation's exact generator order.
`action_nodes[s][j]` names the graph node equal to the required generator-column
identity. A zero identity may reference a zero graph node with an empty
local derivation. Graph terms use `kind="input"` or `kind="node"`; all raw
references are checked, including terms with zero coefficients. Forward node
references are permitted, but cycles are rejected.

For a nonzero algebra, `basis_words[0]` must be `()` and `unit_node` must be
`None`. For the zero algebra, every action has zero columns, every action-node
row is empty, and `unit_node` names a verified node whose polynomial is `1`.

The data types have strict `to_json` and `from_json` methods. Their schemas are
`zipper-generator-action-v1`, `zipper-derivation-graph-v1` and
`zipper-word-basis-certificate-v1`. The presentation hash records the complete
literal input, including the field, generator order and stored coefficient
expressions. Existing Gröbner certificates retain their own schema and
`"basis"` reference terminology; the new shared graph format does not rewrite
those files or their presentation identities.

## Verification and operations

```python
from zipper_algebra.verification.finite import verify_word_basis

# Supply a domain-bound presentation and WordBasisCertificate.
A = verify_word_basis(
    presentation, certificate,
    max_operations=10_000_000, max_dimension=10_000, max_nodes=100_000,
)
coordinates = A.coordinates(target)
a = A.element(coordinates)
b = A.scalar(2)
product = A.multiply(a, b)
```

This is an API sketch; the caller supplies `presentation`, `certificate` and
`target`. Successful verification returns an immutable `VerifiedFiniteAlgebra`.
Its `dimension`, `basis_words`, `field` and `generator_action(name)` expose the
certified data. `coordinates` returns a tuple of exact `FieldElement` values.
`element` constructs a `FiniteElement` from a coordinate vector; `zero`, `one`
and `scalar` construct the corresponding elements. Finite elements support
exact addition, subtraction and multiplication, including scalar arithmetic.

Free polynomials passed to `coordinates` must have the declared free-algebra
parent, even when zero. Finite elements passed to arithmetic must belong to the
same verified algebra object. Two independent verifications of isomorphic or
even identical presentations do not implicitly identify their coordinates.

The certificate stores sparse generator actions. Products are evaluated on
demand using the named basis words and those actions; no cubic-size table of
all basis products or full collection of regular matrices is constructed.
Matrix relation evaluation shares a noncommutative Horner graph, allowing
cancellation before subsequent matrix applications. This is exact arithmetic,
with no sampled parameter values or numerical tolerance.

`VerificationLimit` reports an exhausted operation, dimension or proof-node
bound. The verification operation budget is shared across all checks;
`coordinates` and `multiply` each have a fresh `max_operations` budget, defaulting
to `10_000_000`. These are bounds on counted work, rather than wall-clock limits.
Malformed, incompatible or false data raise `TypeError` or `ValueError`. A failed
or interrupted verification returns no verified algebra. `report` returns a copy
of the recorded counts; subsequent calculations do not change those counts.

`verify_derivations` can check a graph separately with its own operation and
node limits, defaulting to `2_000_000` operations and `100_000` nodes. It establishes the recorded ideal-membership identities; it does
not by itself establish a finite basis or a completed Gröbner basis.

## Reproducing the four-strand finite algebra

First produce the source presentation and its local proof graph, following the
[four-strand square-zero guide](FOUR_STRAND_SQUARE_ZERO.md):

```sh
python examples/four_strand_square_zero.py \
  --singular Singular --output runs/four-strand-square-zero
```

The local action producer
[`examples/four_strand_finite_basis.py`](../examples/four_strand_finite_basis.py)
extends the [four-strand square-zero run](FOUR_STRAND_SQUARE_ZERO.md) with
sparse generator actions and explicit ideal identities for their columns:

```sh
python examples/four_strand_finite_basis.py \
  --source-run runs/four-strand-square-zero \
  --singular Singular \
  --output runs/four-strand-finite-basis \
  --timeout 180 --memory-mib 6144 --degree 24
```

The source run must supply `presentation.json`, `certificate.json` and
`proof.txt`. These encodings are checked against each other and against the
full generic presentation. When source `provenance.json` is present, its
metadata and recorded output hashes are checked against all three consumed
files. The report records `source_provenance_status="present_verified"` or
`"absent"`. This status describes the source-data linkage; mathematical
validation is supplied by the verifier below.
The adjacent
[`four_strand_finite_basis.sing`](../examples/four_strand_finite_basis.sing)
computes the action columns and their local cofactor identities. The output
directory must be fresh and empty; generated files remain under ignored `runs/`.

| Output | Purpose |
| --- | --- |
| `presentation.json` | Exact original defining input. |
| `word-basis-certificate.json` | Named words, six sparse generator actions, shared proof graph and column references. |
| `actions.txt` | Framed word, action and proof data for independent checking. |
| `actions.sing`, `actions.log` | Generated Singular program and its output. |
| `environment.sing`, `environment.log` | Solver/library version and source identification. |
| `report.json` | Candidate data counts, source-provenance status, limits and timings. |
| `provenance.json` | Source revision, changes and source/input/output hashes. |

The framed `actions.txt` uses **one-based** record indices. JSON matrix and
proof indices are zero-based; letters within words are one-based in both
formats:

| Record | Meaning |
| --- | --- |
| `W\|j\|word` | Word `j` of the proposed basis. |
| `ACTION\|s\|j\|n` | Generator `s`, basis column `j`, absolute proof-node number `n`. |
| `A\|s\|j\|coefficient\|word` | A term in the proposed coordinate expression for that action column. |
| `G\|n\|coefficient\|word\|0\|` | A term of the generator-column identity at node `n`. |
| `Z\|n` | An explicitly zero identity at node `n`. |
| `D\|n\|coefficient\|left\|1\|i\|right` | A local derivation term referencing candidate polynomial `i` in the original source graph's candidate prefix. |

Words are comma-terminated lists of one-based generator indices; the empty
word has an empty field. Node numbers are absolute across the source graph
and appended action nodes: `n = source_nodes + (s-1)*d + j`. Derivation
references `i` retain the source candidate-prefix numbering, rather than being
renumbered within the appended action block. `ACTIONS_DONE` records the total
number of required action columns, including those with zero identity targets.

The producer records candidate data. The column proofs, every original matrix
relation and cyclic-coordinate conditions must all be verified before the new
action matrices can be used as a certified finite algebra. Production success
alone does not establish this conclusion.

Verify the resulting finite-basis certificate with the maintained Python API:

```sh
python - <<'PYTHON'
import json
import sympy
from pathlib import Path
from examples.four_strand_finite_basis import (
    input_identity, read_json, source_provenance_status, validate_inputs,
)
from zipper_algebra.algebra import AlgebraPresentation
from zipper_algebra.execution.artifacts import validate_source_snapshot
from zipper_algebra.provenance import capture_provenance, write_output_provenance
from zipper_algebra.verification.finite import WordBasisCertificate, verify_word_basis

producer = capture_provenance()
run = Path("runs/four-strand-finite-basis")
names = ("presentation.json", "word-basis-certificate.json")
paths = [*(run / name for name in names), Path("docs/FINITE_ALGEBRAS.md"),
         Path("examples/four_strand_finite_basis.py")]
if (run / "provenance.json").is_file():
    paths.append(run / "provenance.json")
snapshots = [(p, input_identity(p, bounded=p.suffix == ".json"), p.suffix == ".json")
             for p in paths]
status = source_provenance_status(run, snapshots, names=names)
presentation = AlgebraPresentation.from_json(read_json(paths[0]))
certificate = WordBasisCertificate.from_json(read_json(paths[1]))
A = verify_word_basis(presentation, certificate, max_operations=10_000_000)
validate_source_snapshot(producer)
validate_inputs(snapshots, absent_provenance=run / "provenance.json" if status == "absent" else None)
report = run / "verification.json"
report.write_text(json.dumps({**A.report, "sympy_version": sympy.__version__,
                              "source_provenance_status": status}, indent=2) + "\n")
write_output_provenance(report, producer=producer,
                        inputs=[{"name": p.name, **identity} for p, identity, _ in snapshots])
print(A.dimension)
print(A.report)
PYTHON
```

The producer creates nine computation files plus its ignore marker. This
verification step adds `verification.json` and
`verification.json.provenance.json` in the same ignored run directory. The
sidecar binds the report to the implementation snapshot, exact presentation
and certificate bytes, this documented recipe, the strict input-reading helper,
and the producer provenance when present. The report records the SymPy version
and `source_provenance_status`; supplied producer metadata and both input-file
hash links are validated. Strict bounded JSON readers reject duplicate keys and
nonfinite values. Source or input changes, including newly appearing producer
provenance, prevent publication.

The verified dimension is `186`. The completed reference run checked 1,116
column identities, all 1,563 local proof nodes with 16,683 derivation terms,
5,766 defining-relation columns and 186 cyclic-coordinate identities. Its six
sparse generator actions contain 14,511 nonzero entries. The report includes
`verified=True`, `dimension=186`, `action_identities=1116`,
`derivation_nodes=1563`, `relation_columns=5766` and `cyclic_words=186`.
The reference verification used 249 Horner nodes and 2,881,816 counted
operations, finishing in approximately 65 seconds including JSON loading.
These timings describe that local run; operation counts can change with the
implementation.

This verifies the finite word basis and its generator actions directly. The
independent GAP route described in the square-zero guide proves the completed
basis and all 186 products `w b w = 0`. Separate finite-algebra API validation
checked `w != 0`, `w^2 = 0` and seven selected `w b w` products; these controls
are separate from the finite-basis verification recipe above.

## Exact working arithmetic

Repeated parameter-field calculations use SymPy's sparse fraction fields,
with automatic numerator/denominator cancellation [1, 2]. This is internal
working arithmetic. It leaves the public literal coefficients, presentation
hashes and certificate encodings intact. Conversion back to a public field
element can produce a different representative with cancelled factors; its
own denominator conditions then govern any explicitly requested specialization.
The original literal input retains its original denominator data.

For repeated matrix-vector calculations over `K = Frac(R)`, where `R` is the
parameter polynomial ring, the verifier writes each generator action as
`M_g = A_g/d_g` with polynomial `A_g` and nonzero polynomial `d_g`. A Horner node
representing `P_n(M)` receives a common denominator `D_n`. For a seed `U/S`,
the node computes the polynomial vector `V_n = D_n P_n(M) U`, and restores the
fraction-field vector `V_n/(D_n S)` at the output boundary. Denominators can be
arbitrary parameter polynomials. Common denominators and exact polynomial
quotients are prepared outside the matrix-vector loop, so its repeated
arithmetic uses polynomial addition and multiplication without a fraction gcd
at each accumulation.

This is exact computation over the declared fraction field. Clearing these
working denominators does not prove freeness over `R` or assert a dimension at
parameter values where the relevant expressions are undefined.

The existing cofactor and Gröbner verification interfaces retain their formats
and arithmetic behavior. A completed Gröbner basis can be used to produce the
finite-basis witnesses, but the basis theorem above depends only on the
submitted ideal identities, matrix relations and cyclic-coordinate checks.
